## Milestone card

Use this structure when a step needs more detail:

- **Outcome:** What will be true when this milestone is complete?
- **Concepts:** What should the learner understand first?
- **Current system:** Where does this concern belong and who owns the decision?
- **Design decisions:** What alternatives and tradeoffs need discussion?
- **Learner exercise:** What should the learner attempt?
- **Hint ladder:** What is the smallest next hint, followed by pseudocode or a focused example if necessary?
- **Verification:** Which test, observation, query, or experiment will provide evidence?
- **Production lens:** Which real operational concern is relevant here?
- **Reflection:** What principle transfers to another project?
- **Deferred work:** What was deliberately left for later?

## Progress recap

After every completed chapter, and whenever progress is requested, show the entire curriculum as a numbered table of contents:

1. Foundational model ✅
   - 1.1 Core concepts and vocabulary ✅
   - 1.2 Architecture and boundaries ✅
2. Working vertical slice 🔄
   - 2.1 First implementation ✅
   - 2.2 Focused verification 🔄
3. System integration ⬜
   - 3.1 Cross-boundary integration ⬜
   - 3.2 End-to-end verification ⬜

Use `✅` only when the completion evidence has been satisfied. Keep skipped and deferred lessons visible with `⏭️` and `🕒`. After the table of contents, name the next numbered lesson and add evidence details only when they are useful.

After the table, distinguish:

1. the next core lesson;
2. optional extensions;
3. future product or deployment work outside this curriculum.
